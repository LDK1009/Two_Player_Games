# 추천 2인용 미니게임 10개 설계

## 목표

한 대의 Android 기기를 두 사람이 함께 잡거나 마주 보고 사용하면서 별도 설명 없이 5초 안에 시작할 수 있는 미니게임 10개를 제공한다. 모든 게임은 15~60초 안에 승패 또는 공동 결과가 나오며, 숏폼 영상에서 핵심 재미가 즉시 보이도록 구성한다.

## 구현 방식

선택안은 **독립 게임 10개와 공통 게임 셸의 조합**이다. 공통 셸이 규칙 안내, 3초 카운트다운, 일시정지, 결과, 재경기, 홈 이동을 담당하고 각 게임은 입력·판정·렌더링만 소유한다. 게임끼리 직접 import하지 않으며 공통 기능만 `src/shared`를 통해 사용한다.

설정만 바꿔 복제하는 단일 엔진 방식은 제작은 빠르지만 게임이 비슷해지는 문제가 있어 사용하지 않는다. 모든 게임을 고급 물리 시뮬레이션으로 만드는 방식은 첫 릴리스의 범위와 테스트 비용이 과도해 사용하지 않는다.

## 게임 목록과 완료 조건

### 1. 핑거 스모

- 두 플레이어가 각자 캐릭터를 드래그해 중앙 원에서 상대를 밀어낸다.
- Planck.js 원형 바디의 충돌과 반발을 사용한다.
- 먼저 원 밖으로 완전히 밀려난 플레이어가 패배한다.

### 2. 정지! 먼저 눌러

- 두 버튼을 누른 상태로 대기하고 화면이 초록색이 되면 먼저 손을 떼는 사람이 승리한다.
- 빨간 화면에서 먼저 손을 떼면 부정 출발로 즉시 패배한다.
- 랜덤 대기시간은 1.5~4초다.

### 3. 미니 에어하키

- 세로 경기장의 위쪽은 P2, 아래쪽은 P1이 조작한다.
- 패들과 퍽은 Planck.js로 충돌하며 각 플레이어는 자기 진영 안에서만 움직인다.
- 제한시간 45초 또는 5골 선취로 종료한다.

### 4. 둘이서 로켓

- P1은 왼쪽 엔진, P2는 오른쪽 엔진을 길게 눌러 로켓을 조종한다.
- 두 엔진의 합은 상승력, 차이는 회전력으로 변환한다.
- 30초 동안 장애물을 통과한 체크포인트 수를 공동 점수로 기록한다.

### 5. 우리 얼마나 통할까

- 질문마다 두 선택지를 위·아래 플레이어가 동시에 고른다.
- 두 선택이 모두 끝난 뒤에만 답을 공개한다.
- 7문제 중 일치 개수와 궁합 문구를 결과로 보여준다.

### 6. 폭탄 설명서

- 화면 위쪽 P2 영역에는 랜덤 해체 규칙, 아래쪽 P1 영역에는 폭탄 패널을 표시한다.
- 선 색, 숫자, 기호 순서가 매 라운드 달라진다.
- 45초 안에 3단계를 맞히면 공동 승리, 오답 2회 또는 시간 초과면 실패한다.

### 7. 치킨 버튼

- 두 사람이 각자 버튼을 누르고 있는 동안 점수가 증가한다.
- 보이지 않는 랜덤 폭발 시점 전에 손을 떼야 점수를 확보한다.
- 먼저 손을 떼면 안전하지만 상대가 더 오래 버티면 상대가 승리하고, 폭발까지 누르면 패배한다.

### 8. 색깔 함정

- 색상 이름과 실제 글자색이 다르게 표시된다.
- 각 플레이어가 자기 영역의 실제 글자색 버튼을 먼저 누른다.
- 10라운드 합산 점수가 높은 플레이어가 승리하며 오답은 1점 감점한다.

### 9. 비밀 예측

- 각 플레이어가 상대의 선택을 예측한 뒤 자신의 실제 선택을 고른다.
- 모두 입력한 후 동시에 공개하며 예측 성공마다 1점을 얻는다.
- 5라운드 합산으로 승자를 결정한다.

### 10. 기울기 미로

- 기기 가속도 값을 중력 방향으로 변환해 공을 움직인다.
- 두 사람이 기기 양끝을 잡고 45초 안에 세 개의 체크포인트를 순서대로 통과한다.
- 벽 충돌 횟수와 완료시간을 공동 결과로 표시한다.

## 화면 구조

### 홈

- 상단에 앱 이름과 설정 버튼을 둔다.
- 2열 카드 그리드에 게임 번호, 이름, 대전/협동 태그, 예상 플레이시간을 표시한다.
- 최근 플레이한 게임과 최고 기록은 MMKV에 저장한다.

### 공통 게임 셸

- `ready`: 한 문장 규칙과 시작 버튼
- `countdown`: 3, 2, 1 애니메이션
- `playing`: 게임 HUD와 남은 시간
- `result`: 승자 또는 공동 점수, 재경기, 홈 버튼
- Android 뒤로가기는 플레이 중 한 번 확인한 뒤 홈으로 이동한다.

### 양방향 사용성

- P2 전용 텍스트와 버튼은 180도 회전해 마주 보는 사람이 읽을 수 있게 한다.
- P1은 코랄, P2는 블루를 사용한다.
- 승패를 색상만으로 구분하지 않고 P1/P2 텍스트와 아이콘을 함께 표시한다.

## 폴더와 인터페이스

```text
src/
├── app/
│   ├── index.tsx
│   └── games/[gameId].tsx
├── views/
│   ├── home/
│   └── game/
│       ├── GameRouteView.tsx
│       └── _components/games/<GameName>Game.tsx
└── shared/
    ├── components/game/GameShell.tsx
    ├── constants/games.ts
    ├── hooks/useGameCountdown.ts
    ├── store/useGameRecordsStore.ts
    ├── types/game.ts
    └── utils/game/*.ts
```

`GameDefinition`은 `id`, `title`, `mode`, `durationSeconds`, `accent`, `route`를 가진다. 런처와 동적 라우트는 같은 레지스트리를 사용해 목록과 실제 게임이 어긋나지 않게 한다.

게임 컴포넌트는 다음 인터페이스를 따른다.

```ts
type GameComponentProps = {
  phase: 'ready' | 'countdown' | 'playing' | 'result';
  onFinish: (result: GameResult) => void;
  roundKey: number;
};
```

## 상태와 데이터 흐름

1. 홈의 게임 카드를 누르면 `gameId`가 동적 라우트로 전달된다.
2. `GameRouteView`가 레지스트리에서 정의와 게임 컴포넌트를 선택한다.
3. 공통 셸이 `ready → countdown → playing → result` 전이를 관리한다.
4. 게임은 입력을 Reanimated SharedValue 또는 Planck.js 월드에 반영한다.
5. 승패가 확정되면 `GameResult`를 셸에 전달한다.
6. 셸은 결과를 표시하고 최고 기록만 Zustand persist/MMKV에 저장한다.

프레임 단위 좌표와 물리 상태는 Zustand에 넣지 않는다.

## 오류 처리

- 알 수 없는 `gameId`는 홈으로 이동할 수 있는 오류 화면을 표시한다.
- 센서 사용이 불가능하면 기울기 미로에서 재시도와 홈 이동을 제공한다.
- 게임 타이머와 센서 구독은 화면 이탈 및 재경기 시 반드시 정리한다.
- 햅틱 또는 효과음 실패는 게임 진행을 막지 않는다.

## 테스트 및 검증

- 게임 판정, 점수 계산, 랜덤 라운드 생성은 순수 함수로 분리한다.
- `node:test` 기반 테스트에서 부정 출발, 동점, 시간 초과, 오답, 경계값을 검증한다.
- 모든 게임은 시작부터 결과와 재경기까지 수동 확인한다.
- `npm run typecheck`, `npm run lint`, `npm test`, Expo Router 경로 확인을 통과해야 한다.
- 네이티브 의존성을 추가하지 않으므로 기존 개발 빌드를 재사용한다.

## 범위 제외

- 실제 결제 화면과 실광고 노출
- 사용자 제작 질문과 원격 콘텐츠
- AI 상대 및 싱글플레이 모드
